「現状」欄で区別する。実機で確かめていない項目は「未確認」と明記する。

## 1. この文書が答える問い

TIL は「押したキーが光る」だけの道具ではなく、**実物を触ってもらうための説明装置**である。
一方で Vial 対応機を繋げば、その機の物理配置は端末から読める。両者をどう組み合わせるかを
決める。

## 2. 情報を 3 層に分ける

| 層 | 名前 | 中身 | 出どころ | 無いと何ができないか |
|---|---|---|---|---|
| A | 製品プロファイル | TrackPoint の位置と見た目、ガイドツアー、練習文、オートレイヤー表示の模擬、Vial UID、`customLayerKeys`、customKeycodes の予備、`vial.json` の KLE と labels の写し | TIL のコード（`ui/layouts/*.js`）。値の正本は `qmk-config` / `rmk-config` | TP が描けない・ツアーが出ない・模擬が動かない |
| B | 端末定義 | KLE（配置・寸法・matrix 座標）、layout options の選択肢、matrix 次元、customKeycodes、製品名 | 端末の `vial.json`（キオスク経由の XZ 展開）。取れないときは A の写し | 個体差（Space 分割・エンコーダ有無）が描けない |
| C | 端末状態 | 保存された layout options、キーマップ、押下状態、unlock 状態 | Vial / VIA プロトコル | 刻印が実物とずれる・点灯しない・レイヤーが追従しない |

**原則**

1. **A は「製品にしか無い知識」だけを持つ。** B で表せるものを A に二重に持たない。
   VIA / Vial の定義には**ポインティングデバイスという概念が無い**ため、TP の位置は
   A が持つしかない（`vial-gui` の `keyboard_comm.py` / `layout_editor.py` を突合済み）。
2. **B・C は接続中だけ有効。** 切断とプロファイル切替で捨て、A の絵へ戻す。
3. **A が無い端末には B・C だけで描く。** TP もツアーも**推測しない**（出さない）。
4. **KLE は A にも同梱する。** 未接続でも、また端末定義を取れない経路（ブラウザ / WebHID は
   XZ 展開を持たない）でも、同じ規則で描けるようにするため。

> A の KLE は「B の代わり」ではなく **A の一部**である。未接続時に使うのはこの写しであり、
> 接続は要らない。

## 3. 決定事項（2026-09-09・ユーザー判断）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 未接続時の既定ボード | **OLSK60**。起動後にスタッフメニューで他も選べる（現行どおり） |
| 2 | 表示ロック（接続しても絵を変えない機能） | **不要**。「実物が無いときに既定を出す」は既定ボード選択で足りる |
| 3 | 未接続で見せる OLSK60 の構成 | **3-Split・エンコーダ無し**（現行の見た目を維持）。layout options では値 `2` |

| 5 | Vial 非対応機 | **汎用テンプレートで割り切る**（`KeyboardEvent.code` で点灯） |

## 4. 表示の決定規則

```
接続していない
└─ 既定ボード（スタッフ設定・初期値 OLSK60）を A で描く
   └─ 製品プロファイルなら TP・ツアー・練習文も出す
   └─ 構成は A の defaultLayoutOptions（OLSK60 = 3-Split・エンコーダ無し）

Vial 機を接続した
├─ UID または VID/PID が製品プロファイルに一致（= 登録機）
│   └─ その A に、B の KLE と C の layout options で選んだキー集合を重ねる
│       ・位置と寸法は端末側 ・刻印と KeyboardEvent.code は A から継承
│       ・TP、ツアー、練習文は A のまま ・エンコーダは端末に有るときだけ描く
└─ 一致しない（= 未登録機）
    ├─ 端末から vial.json を取れた → **B・C だけで描く**
    │   ・TP なし ・ツアーなし ・名前は定義の name
    │   ・刻印は接続後にキーマップから埋まる（A の刻印表が無いため接続前は空）
    │   ・ブラウザ打鍵での点灯はできない（matrix ↔ KeyboardEvent.code の対応が無い）
    └─ 取れない（WebHID 経路） → 汎用テンプレートへ落とし、理由を画面に出す

Vial 非対応機 / 何も繋がっていない
└─ 既定ボードまたは選択したテンプレート。KeyboardEvent.code で点灯
```

切断時は B・C を捨てて A の絵に戻す。プロファイルを切り替えたときも同様。

## 6. 表示領域への収め方

`fitKeyboard()` は `min(上限, 横幅 / unitsWide, 縦幅 / unitsHigh)` で 1u の画素数を決めるため、
**外形が何であれ領域には収まる**。問題は「収まるが小さすぎる」ことである。

- フルサイズ（22.5u × 6.5u）を 60%（15u × 5u）と同じ枠に入れると 1 キーが約 2/3 になる
- 展示では来場者が画面を操作しないため、**横スクロールは使えない。縮小一択**

対処（未実装・優先度は低い）:

1. 刻印の文字サイズに下限を置き、下回る場合は副刻印（Shift 面）を省く
2. キーボードパネルの高さを固定ではなく外形の縦横比に応じて配分する
3. フルサイズを超える機は「全体は縮小、押したキーだけ拡大」など別表現を検討

## 7. 現行との差分（実装の単位）

| 項目 | 状態 | 補足 |
|---|---|---|
| UID による製品判定、端末構成の重ね描き、候補の優先、切断時の破棄 | 実装済み | PR #44 / #45 |
| **S3: 未登録 Vial 機を定義だけで描く** | 未実装 | `composeOverlay` を「A 無し」でも成立させ、定義由来の一時ボードへ差し替える。切断で戻す |
| **S7: 定義を取れない未登録機を汎用へ落とす** | 未実装 | 小。理由の表示を伴う |
| **A の座標を同梱 KLE から導く** | 未実装 | `defaultLayoutOptions: 2` を A に持たせ、手書き `keys` から座標・寸法・matrix を落とす。A に残るのは matrix 座標 → 刻印・`KeyboardEvent.code`・修飾（`layer` / `win` / `homing`）の対応表。**見た目は変わらない**（値 2 = 現行と同一）。副作用として `vial.json` 更新時の二重管理が消え、未接続でも構成を切り替えられる素地ができる |
| 汎用テンプレート（ANSI 60% / フルサイズ） | 現行維持 | KLE を持たないので手書き `keys` のまま。「KLE があれば使い、無ければ `keys`」の二本立て |
| 表示ロック | 作らない | 決定 2 |
| 小さすぎる表示の対策 | 未実装 | §6 |

## 8. 検証の考え方

- `tools/vial-layout.test.js`: KLE の解釈・layout options の bit 詰め・合成（ホスト単体）
- `tools/boards.test.js`: プロファイルの整合（UID・matrix・customKeycodes・ツアー対象）
- `tools/visual-check.js`: 3 画面サイズ × 両テーマでの実描画と、状態遷移の fixture
- **合成 fixture の成功を実機確認済みと扱わない**（`AGENTS.md`）。S3 / S9 は実機が要る
- `tools/check-board-sources.js`: A の写し（UID・matrix・customKeycodes・labels・KLE）が
  正本と一致しているかを突合する。正本の `qmk-config` / `rmk-config` は private なので
  **この repo へ取り込まない**（submodule にしない）。実行時にローカルパスを渡すだけで、
  差分の所在だけを表示する。正本が無ければ未確認として skip するため、CI では走らない
